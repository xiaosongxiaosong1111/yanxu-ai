Claude的数据任务见[全国数据实施手册](CLAUDE_NATIONAL_DATA_RUNBOOK.md)及[批次操作日志](work_nodes/NATIONAL_DATA_BATCH_LOG_TEMPLATE.md)。Claude负责正式采用数据，Codex负责官网发现、共享读取连接和独立验收；两边使用独立分支和数据目录。

## 2. 本轮怎样测

新样本与旧72单位ID无交集，覆盖31个省级地区。按“原始有/无登记网址 × 学校/科研机构名称启发式”分四层，每层30个。名称分类只用于取样，不当作官方机构类型。刻意等额分层用于找失败，**不能外推全国成功率**。

没有清空真实公开包的可用资料：85个单位带入109份已核SHA的本校年度原件；60个原始无网址单位中，34个仍有公开声明，26个确实既无登记网址也无可用本校原件。全部知识库存于临时目录。

真实调用生产 `ResearchTools.run('discover_official_entry',...)`。此组件做官网导航，不自行调用模型或元宝。另一个独立人工对照使用公开联网搜索，但不把人工找到的URL注入自动基线。**本轮不是完整AI＋元宝Agent端到端评测。**

## 3. 两轮真实结果

两轮样本文件字节相同，公开包、学校范围、预算和每主机至少2秒间隔不变；生产代码比较时只改变了HTTPS客户端的默认端口行为。

| 指标 | 修复Host前 | 修复Host后 |
| --- | ---: | ---: |
| 不同单位数 | 120 | 120 |
| 公开HTTP读取尝试 | 394 | 390 |
| 保有独立站入口 | 65 | 65 |
| 授权域完整HTML响应 | 60 | 60 |
| 目标年度材料记录 | 50 | 49 |
| 独立站新取得的实质正文 | 25 | 24 |
| 通过质量准入的原文保存 | 24 | 23 |

**没有观察到总体提升。** 两轮取得HTML响应的单位集合相同。HTTP200和SHA完整只证明收到响应，不能保证已排除所有JavaScript挑战，更不能当作已读到招生正文。

目标材料差异集中在北京大学：前后入口响应和后续路径变化后，统计脚本 `writeLog.jsp` 等消耗导航预算，仍会漏掉目标。这暴露了独立的导航调度问题；实际网站状态会变化，不能把前后所有差异都直接归因于一行Host修复。

原计分器只认部分主标题结构，缓存CHSI文章的可见H2存在漏认；表中“独立站新正文”单列，不用缓存正文列的0宣称旧原件全部不可读。原计分门槛没有为改善数字而放宽。

逐校状态见[修复前CSV](reports/official-discovery-round2-20261109/baseline.csv)、[修复后CSV](reports/official-discovery-round2-20261109/after-host-fix.csv)，汇总及源码指纹见[summary.json](reports/official-discovery-round2-20261109/summary.json)。

## 6. 已修复与仍需解决的共性

| 共性 | 当前结论与处理 |
| --- | --- |
| HTTPS Host默认端口行为 | **已修。** `_PinnedConnection`继承HTTP连接却使用TLS，默认端口仍80，自动Host附上:443；改为TLS默认443，HTTP仍80，非默认8088/8443仍保留 |
| 无专业候选时原地导航循环 | **已修计划回退。** 同单位/年度/文种已尝试导航后转有限搜索；已搜或额度耗尽则停止；没有预选学校时只承接已经实际执行的当前年单位 |
| 没起点的导航冷启动 | **仍缺。** 单独导航组件不会发起官网搜索；需要机构身份/官网发现与目标年度文种检索分阶段，不能靠人工补几所域名代替 |
| 脚本和栏目调度 | **仍缺。** 统计脚本、先脚本后文章、局部深度优先可能耗尽8次导航额度，应优先可见目标链接并防栏目饥饿 |
| 动态门户和标题结构 | **仍缺。** hash路由被剪除、JSON/CMS门户缺适配、p/strong等文章标题漏判；必须识别真实文章结构并保留逻辑路由 |
| 来源归属和外链PDF | **仍缺。** 新主机、主管单位共享站、跨域附件需要可回放的精确证明；当前HTML型归属验证不能直接处理外部PDF，不应放大全站白名单 |
| 网络与错误类型 | **仍缺。** 只试DNS首地址、旧URL/重定向、证书与真实访问限制分别保留；不关TLS、不绕挑战；读取错误也不能统一吞成归属未证 |
| 全国目录与字段发布 | **Claude数据线负责。** 官网定位、原文取得、行解析、资格语义、正式发布是不同节点，不能只填布尔完整标志 |

Host缺陷有真实同IP、同URL、同UA的对照：原自动Host连接被断开；仅显式去掉默认端口后HTTP200、42,457字节、标题“复旦大学研究生招生网”。一行修复后的原生产读取函数、不加自定义transport同样成功。它证明该兼容问题真实存在，**不证明全样本成功率提高**。原件与对照见[Host证据](../tests/fixtures/official_discovery/transport_host/host-header-homepage-comparison.json)和[修复后生产读取](../tests/fixtures/official_discovery/transport_host/host-fix-production-after.json)。

其他共性有独立无网生产代码诊断，见[修复前探针](reports/official-discovery-round2-20261109/pre-fix-gap-probes.json)。该文件是旧行为快照；计划循环现已修复，不能把这些合成探针算成真实网站成功。

## 7. 取证边界、验证和复现

本轮无付费搜索/模型、无用户Key/业务数据库访问、无新CHSI请求，未改全国目录或个人知识库。独立人工读取与生产DNS固定连接是不同链路，不能用前者成功直接替代生产成功。

原A/B报告没有回写。旧工具漏把 `collectors/discovery.py` 放进原指纹清单，baseline结束54秒后补采，不能声称baseline从开始便持续监测此文件；修复后运行有开始、结束及重放后指纹。执行历史、Git差异和修复前线级对照另行支持版本关系。原重放的388/383指去重录制条数，实际新网络请求为0；逐请求/原文不完全一致，不称为逐字确定性重放。

实测后新工具已硬化：关键传输文件进入指纹、Windows保留目录大小写拒绝、全重放清单在读取前检查路径/符号链接/大小/SHA，包括从未请求的缓存记录；真实HTTP、录制条数与重放调用数分别记录。旧录制与计分阈值保留，见[方法更正说明](reports/official-discovery-round2-20261109/methodology-notes.json)。

新审计工具21项、Host/SNI两项、计划回退四项测试通过；与相关采集、来源和研究服务合跑337项通过。独立安全复查通过，审计工具含分支覆盖88%、计划模块独立回归覆盖94%。本轮未重复旧整库或浏览器全套，亦未运行完整付费Agent链路。

新工具默认只取样不联网，真实执行必须显式`--live`，输出目录须全新：
