## 核心判断

项目已经有可验证的三态规则、命题作用域科目距离、Pareto、路线和最小条件调整算法，也有原文留档、字符跨度、质量准入、撤信和向量派生机制。下一阶段最有价值的工作，是让用户当前问题驱动官方原文进入可计算候选、资格及费用字段，形成可以补证和复算的闭环。

当前公开包的限制也很明确。931 个年度确认单位中只有 135 校有目录方向，且 22,356 个方向的资格均还待核。全国来源搜索能力不会自动增加可计算候选；现阶段找到目录库外学校的公告，仍主要增加来源，尚不能生成新的结构化专业。这一能力缺口应优先于增加排序公式或展示更多分数。

## 已定位并修复的正确性问题

### 1. 路线与条件放宽丢失反事实候选

Agent 原本先按当前硬条件筛选并压到 12 个方向，再计算“多准备一门”和“放宽地区”。本来被换科上限或地区排除的方向已不在输入中，后续情景无法将其找回来。

实际公共南开样本有 226 条原始方向记录。以 101/201/301/408、全日制和当前换科上限 0 计算，修前 Agent 的三条路线是 **7/7/7**，完整同校输入应为 **7/12/173**。修复后恢复为 7/12/173，展示候选仍为 7 项，资格均仍待核。

修复保留受原学校、年度、查询与发布版本约束的研究池；显式 `program_ids` 继续遵守用户选择。明确允许放宽地区时，只在同查询、同年度、同发布版本及学校硬范围内补充本地目录读取。部分扫描和只继承展示候选的情况不会宣称研究池完整。

### 2. 依据失效后，派生学费与工具缓存仍可能被采用

独立复现中，两份来源一致的年费 12,000 元曾参与计算；第二份来源撤信后，字段草案已降级，但候选仍保留旧金额，预算 10,000 元仍被判为“已知学费超预算”。同参数工具 memo 也可能在重新检查来源前返回旧原文与 `usable=true`。

修复后，程序根据当前有效来源重建自己拥有的派生学费和冲突状态，保留正式目录原值和外部审核要求；金额或作用域变化会使相关算法缓存失效。整链复现现在恢复未知学费和 `unknown`，不再用已撤信金额排除候选。memo 复用前重新核对可信来源，失效原文拒绝复用，搜索缓存清空失效正文，不自动追加付费请求。

跨轮来源同时按当前学校、参考年度与当前权威知识记录重核，避免他校或不适用年度的旧证据继续进入当前账本。

另外补齐否定校名边界。明确“不考虑/排除”的学校不再成为唯一正向意向；“不想考408，考虑南开”不会误杀学校偏好。含“除了”等语义有歧义的表达保持未确定，由后续用户确认处理。

### 3. 计划账本没有进入模型上下文

原系统提示要求遵循 `next_actions`，但捕获的完整两轮模型输入中，没有实际计划和具体查询，计划主要出现在报告中。修复后每轮发送当前目标、下一步动作、缺口数量、预算和完成条件。长历史压缩或来源失效重置后也保留这份有界计划，不夹带整份原文。

这使计划成为可执行的模型输入，尚不代表已经证明所有模型都会按最优顺序行动。真实模型的步骤选择、成本和失败恢复仍需专门评测。

### 4. 关键浏览器流程

- 元宝鉴权切换时，保留编辑节点的逻辑只按 `name` 寻找 radio，导致两个选项的值都变为 `api_key`。现在按名称、类型和值匹配，保留中文输入保护及复选数组语义。
- 知识库原文定位曾从 URL 删除 `segment_id`，刷新后失去片段位置。现在首次打开、切换片段、复制、刷新和历史导航均保留合法位置。
- 320px 设置页宽度从 348px 修正为 320px，三项连接页签使用等宽布局，保留现有视觉方向和字号。

### 5. 请求内原件校验与返回前状态复核

同一份 6 MiB 合成原件、128 个片段，关键词召回 40 个候选并返回 8 项，原实现完整哈希 161 次，累计约 1.013 GB。修复使用请求隔离的校验作用域，返回前再按最终唯一来源做新鲜复核，实际完整哈希降为 2 次，约 12.58 MB。跨请求、线程、异步任务、嵌套作用域及不同 Store 均隔离，不引入永久信任缓存。

新增回归还确认并修复了召回后、返回前发生原件篡改、撤信或提取代次切换时的过滤。哈希改为 64 KiB 流式读取，保留 8 MiB 上限。

这是校验读取量的改进。独立样本仍执行约 3,742 条 SQL、82 次连接，耗时与原先 3.45/3.79 秒接近，不能宣传成整体查询显著提速。下一步应批量读回，减少连接与重复版本查询，同时保留最终鲜活校验。

## 算法独立检查与仍需优化的设计

三态规则、命题作用域和 Pareto 并非页面上的算法标签。Pareto 与独立逐对支配定义做了 600 组随机差分，结果全部一致；带作用域和 OR 选项的科目距离做了 800 组对照，结果全部一致。800 个反链点上，Fenwick skyline 约 1.669 ms，逐对比较约 345.248 ms，结果一致。这是单机微基准，不是线上 SLA。

排序仍有设计局限。费用按当前候选做 min-max 归一化，加入一个高价且被 Pareto 支配的方向，会改变原有 A/B 的刻度并使排名反转。建议下一轮使用明确且可解释的固定预算锚点或稳健刻度，保留缺失分项区间，再评估偏好敏感性。不要在无效果对比时静默改变用户排序语义。

稳定性结果的频率包含基线，而 `scenario_count` 只计额外情景，建议明确返回观察次数与分母。12 项决策分析实测重复调用 `match_programs` 27 次，约 33.8 ms，目前不是主要瓶颈，扩大研究池后可复用基线与信息价值计算。

## 下一阶段按收益排序的任务

| 顺序 | 工作 | 验收方式 |
| --- | --- | --- |
| 1 | 官方原文生成当轮临时候选 | 选择原来不在 135 校目录中的学校，完成搜索发现、官方原文读取、专业/方向/学习方式/科目 OR 组规范化、字段原句定位与校验，最后真实进入比较；不得直接覆盖正式目录 |
| 2 | 资格与费用补证闭环 | 按学校、学院、方向和实际年度建立条件清单，覆盖普通本科、同等学力限制、工作年限、跨考加试样例，三态均有真实依据；费用分别记录年费/全程及适用范围 |
| 3 | 原件入库与知识维护队列 | 分开显示元数据、可重提取原件、待取全文、待 OCR、年度待核、可检索片段和向量状态；先利用现有公开原件，显式维护，不把摘要一键升级可信 |
| 4 | 批量检索读回与受控语义路由 | 降低每次检索的连接/SQL 次数，对比相同问题、作用域和预算的来源召回及必要引文；远端语义由任务级明确许可和独立预算控制，不能把 `allow_remote` 直接改 true |
| 5 | 以用户行动组织交互 | 待核原因直接进入“让 Agent 补证”，AI 识别条件可逐项编辑确认，已知条件变化先本地重算；索引 desired/serving/staging 等运行细节收起，主层给可用状态和下一步 |
| 6 | 统计数据与新评测集 | 学校线、专业线、录取初试分布、最终成绩公式、统考计划分开存放；新增未参与调试的问题与多来源干扰项，不改旧金标制造提升 |

自然问句解析也存在可测边界。同一临时库中“计算机考研的初试科目是什么”命中 128 段，在“的”后插入一个空格就变 0；“计算机 初试科目”则命中 64。应区分自由问句和精确关键词模式，再统一空格、标点和代码混合问法，保留原有精确关键词契约。

远端 Embedding 在 Agent 路径目前固定不授权付费查询，会出现 `vector_remote_requires_action` 并降级关键词。这是费用门禁，应补任务级许可和清晰提示，不应绕过门禁来显示“模型已参与”。
