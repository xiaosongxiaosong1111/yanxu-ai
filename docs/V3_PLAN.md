# V3：从资料查询到可解释的备考决策

2026-10-29。本轮在已确认的冷白、炭黑、钴蓝界面上增加四项能力，同时修复排序、目录版本、缓存与交互问题。仅本地开发和验证，不推送 GitHub、不部署、不修改其他项目或密钥。

## 用户流程

保持「院校专业」「我的方案」两个主导航。先填写备考科目、地区与预算，再查看真实收录范围内的方向；收藏后在「我的方案」查看路线、跟踪变化、补充证据。高级功能按任务切换，不在首页堆叠按钮。

| 能力 | 计算与数据 | 展示与边界 |
| --- | --- | --- |
| 备考路线 | 按考试单元比较最多调整 0、1、2 科的候选集合；保留其余条件 | 区分方向数、院系专业数、学校数；未知科目单独计数；候选卡展示前 20 项，覆盖数计算全量传入资料 |
| 最小调整 | 只枚举用户允许的换科上限、地区和年学费，最多 128 种组合 | 说明改动字段、新增与移除项；待核实方案与已知条件匹配方案分开；不会修改学历、背景或工作年限 |
| 招生变化雷达 | 从当前已收藏方向订阅官方目录；留存新旧来源摘要与字段变化 | 服务运行时每小时检查，并支持手动检查；本站查看，不含邮件/短信；无法确认年度时待复核，不认定停招 |
| 元宝资料补证 | 从真实学校与年度生成 SearchPro 查询，再读取可归属的官方原文 | 展示精确引文、页码、来源、年度及作用范围；搜索片段不入库；候选值须复核，不自动改招生数据；无 Key 明示未配置 |

## 模块与接口

- `grad_engine.py`：资格三态、考试单元兼容、偏好排序与 Pareto 分析。未知学费保留空值与分数区间；`ranking_mode` 支持综合、科目、费用。
- `planning_engine.py`：`plan_routes`、`suggest_adjustments`，返回可解释的集合变化。
- `radar.py`：订阅、官方来源刷新、变化事件和本地留档；`data/runtime/` 不入仓库。
- `public_sources.py`、`source_proof.py`：固定学校来源边界、IP 固定的公开地址读取、原文补证与作用域核验。
- `snapshot_cache.py`：按资料版本复用核验结果；来源变化后重新核验，返回副本避免修改缓存。
- `enrichment.py`：将人工核对的费用与学制按同年、同校、明确方向白名单附加到目录；逐份验证原文与精确页码，失败保留未知，重采目录不会丢失独立证据。
- `static/workbench*.mjs`：在现有方案页按需加载高级功能，取消过时请求，保持返回路径和滚动位置。

所有 API 沿用 `{ok,data,error}` 信封，失败时显示可恢复原因。
API 每分钟 300 次与静态资源每分钟 1200 次使用独立预算；元宝检索和补证共享每分钟 10 次预算，避免页面资源耗尽算法接口额度。

| 方法与地址 | 输入 |
| --- | --- |
| `POST /api/route-plan` | `{profile,unit_ids?}` |
| `POST /api/adjustments` | `{profile,unit_ids?,allowed_changes,goal_min_candidates?}` |
| `GET /api/radar` | 可选 `program_id`、`unit_id`、`year` |
| `POST /api/radar/watch` | `{program_ids:[]}`，完整替换当前订阅，空数组为取消 |
| `POST /api/radar/check` | `{}` |
| `GET /api/source-tasks` | `program_id` |
| `POST /api/source-proof` | `{program_id,kind}` |

补证类型为章程、费用学制、计划人数、历史分数、调剂、科目变化。个人档案不会拼入公共搜索请求；新项目仅读取 `GRAD_SEARCH_API_KEY`。

## 验收顺序

1. 算法、缓存、版本与安全边界先用失败用例复现，再实现和回归。
2. HTTP 集成测试覆盖参数、方法、Host/Origin、频率限制和异常信封。
3. 真浏览器完成资料筛选、收藏、返回、路线、授权调整、雷达、未配置补证及移动端流程。
4. 检查真实资料覆盖、来源完整性和缺失字段；只报告实际运行的测试、网络调用与截图。

全国索引与全国专业完整度始终分开；2027 资料仅作 2028 规划参考。旧版本保留为证据，新目录只有在相应范围成功解析后才替换当前版本。算法与 AI 都不生成录取概率，不把资格未知包装成可申请。
