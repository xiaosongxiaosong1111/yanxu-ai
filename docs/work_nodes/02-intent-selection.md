## 目标与现有基础

让“只去天津”“优先天津”“不考408”表达不同含义。先在本轮可用的已发布目录范围内筛选、粗排，再精选最多12个候选供后续深查；不能先取前12条再发现都不合适。

已有能力可复用：`propose_profile` 的逐字段用户原句、待确认提案，以及 `continue_research` 的确认合并。AI提案不能提前改变算法输入。`grad_engine` 已有三态资格、预算、考试单元与合法 choice_group OR 方案、排名/Pareto；沿用其语义。

## 必须先建立的失败回归

| 场景 | 预期行为 |
| --- | --- |
| 只去天津 / 优先天津 | 前者是硬条件；后者保留外地，仅影响排序。软偏好不得默默变硬排除 |
| 未填备考科目，但明确不考408 | 可独立提案排除科目；确认后才生效，未填其他科目仍未知 |
| 必考408 / 合法408 OR自命题 | 排除前者；后者保留合法替代方案，并按替代方案重新计算换科，不能借被禁408算零换科 |
| 已准备408但不愿考408 | 备考事实与考试意愿分开，允许形成换科路线，不简单判为矛盾 |
| 自命题同码不同校 / 科目身份不明 | 作用域不混同；存在争议或无法证明替代合法时保持待核，不冒充符合 |
| 单校第13项 / 全局第1001项 / 省份第9校 | 后面的合适方向仍能被选入；用户显式选校最多8所的输入契约保持不变 |
| 前12项均硬冲突，后续有可选项 | 先硬筛、全范围粗排，再精选；用原始完整行计算，不用 `_candidate()` 裁剪摘要或逐页归一化 |
| 缺费用、资格或科目 | unknown 不能当作免费、符合或零换科；保留可解释的待确认项 |
| 用户原句、确认与前端 | 新条件逐字段有原句；提案可读并能确认，新增字段不被前端白名单藏掉；拒绝无证据字段，不改输入对象 |
| 查询范围与异常 | 固定目录 revision；每页检查取消/时间；省份无学校时不回落全国；未扫完明确 partial |

候选新增或替换要有确定规则；已有12条不能永久挡住后续查询发现的更合适方向。候选变化后重算受影响算法，不能沿用旧签名结果。保留真实 `total_in_query`，另报扫描量、硬筛排除/待确认量、精选量和 `scan_complete` 等必要指标，不把筛后数伪装成原总数。
