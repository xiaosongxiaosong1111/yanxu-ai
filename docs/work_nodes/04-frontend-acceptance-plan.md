# N4C2 前端独立验收计划

2026-11-03，只读规划。Claude 负责全部业务代码与正式测试，Codex 仅下发与验收。本次没有运行套件、启动服务、读取用户 DB/Key，亦未修改业务或正式测试。当前6个UI草稿保持冻结，先前18项渲染单元通过不等于C2完成。

## 必验清单（8项）

1. **三种连接隔离与真实测试。** 从正式设置入口切换AI/元宝/知识检索，Embedding默认本机中文BGE、无需Key；远端列表仅含真实支持厂商。使用后端最终元数据，所有返回候选可选，手填/目录往返不丢当前模型。模型目录读取不标连接成功；真实向量测试返回维度/模型身份、再保存后才显示已验证。配置Embedding、移除Embedding均不改变AI/元宝快照；用Fake API检查请求kind及完整流程，不用源码字符串匹配冒充验收。

2. **凭据、收据与错误边界。** Key仅保存在当前内存/输入值，不进HTML value属性、URL、localStorage、日志或截图；退出/换厂商清空。模型、端点、前缀、维度请求等兼容性字段变化后收据作废；只有原草稿保存重试可复用收据，且不再次向量调用。401/403/额度/超时/空响应/缺维度/模型未准备/保存失败都有可恢复提示，不伪造连接或保存成功。向模型名、端点、错误与来源文本注入XSS/带凭据URL，确认只显示安全文本或拒绝链接。

3. **原生输入、焦点与竞态。** 用本机Edge CDP原生composition验证：延迟模型列表、索引轮询、错误提示返回时，活跃输入节点及祖先没有被移除，composition不中止，光标/选区/撤销和新草稿保留。中文候选提交的Enter不能触发测试/搜索；确认结束后只提交一次。迟到的旧厂商/旧模型/旧查询响应不能覆盖新草稿或结果；切页/dispose后没有旧回调写DOM，也不残留重复监听器。

4. **首次准备与无隐式工作。** 冷启动/打开设置/打开知识页/GET状态/后台轮询不下载模型、不调用Embedding、不构建索引。仅明确准备/测试动作可下载或推理，并显示首次约95MB与服务所在设备语义；已校验缓存不重复下载。对Fake调用计数设断言，再将真实固定本机模型测试单独记证；断网/校验失败不显示准备完成。

5. **desired、serving与索引状态。** 使用真实B/C1状态形状验证未建、构建、待更新、失败、可用；当前结构索引、向量索引及配置状态分别展示。新模型建立staging且失败时，保留旧serving，不能把desired模型标签放到旧索引上。主动构建、真正服务端取消、失败重试逐一校验请求与结果；已缓存不重复生成。资料/片段/窗口及缓存统计按后端真实口径显示；未知token/总量写未知，不能显示0或虚假百分比。SQL状态不冒充刚测试过存储连接。

6. **混合搜索与原文闭环。** 主动提交POST retrieve才允许远端Embedding；按键、GET检索和轮询不后台计费。用相同school/year/entry过滤验证hybrid、keyword降级和错误恢复，不能把ANN候选数当全国/全库总数。关键词资料列表原分页保留；命中点击进入N3精读、真实PDF页码/HTML原链接、独立表头与邻接；当前来源撤信、他校/他年/旧extraction或generation、被篡改原件必须拦截，不能使用向量payload的陈旧正文。

7. **性能、轮询与用量。** Fake定时/延迟接口验证无轮询重入/打开details重绘循环，构建中按有界周期取状态，停止/终态/切页不继续累积定时器。快速输入只更新草稿，显式提交一次；重复点击忙态不重复构建/计费。展示实际耗时、向量输入/缓存、已知与未知用量，不能用缓存命中推算费用。真实本机评测遵守CPU threads=2、小批次，浏览器/整库套件错开Claude实施，避免资源争抢污染延迟。

8. **视觉与回归证据。** 320/390/1440/2552宽度无横向溢出，长模型名/错误/版本身份仍可读；主动作简短，技术字段和索引维护折叠，普通正文/输入字号舒适。Tab/Enter、折叠、返回焦点可用。保留现有模型选择、AI/元宝连接、N3资料列表8流程、精读10流程、Agent原生IME回归；新增逻辑含分支覆盖>=80%。交付截图、完整exit/日志、实际执行范围；mock浏览器、真实本机模型/向量库、人工Windows输入法三类证据明确区分。

## 当前依赖与交付判断

C2在A/B/C1验收前尚不能完成，不应由UI猜后端字段。需要冻结：Embedding预设与观测身份/维度、desired与serving profile、向量进度的资料/片段/窗口口径、缓存/已知未知用量、状态/构建/取消、retrieve作用域和降级响应。现有knowledge.mjs/knowledge-reader.mjs尚无N4混合入口或向量状态，旧草稿也没有完整浏览器证明。

两处合同需要先统一：C2要求显式本机准备入口，但现草稿只有缺模型报错、没有准备接口；C2要求用户取消，C1却写“若B已支持则接入”，现向量UI草稿也无服务端取消。若A/B/C1不提供这些能力，C2不得以abort前端fetch或静态提示冒充后端准备/取消，需先补后端合同或明确调整交付范围。资料/窗口/复用统计同理，未有字段则如实标未知，不造进度。

当前没有不可克服的前端技术依赖；上述属于前序服务契约与验收门槛。真实金标完整链路另依赖冻结原件、实际固定权重和可运行Milvus，mock UI无法替代。原金标字节/query/答案、scope/top_k/阅读预算均不得为界面或效果改写。
