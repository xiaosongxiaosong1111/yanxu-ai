## 实际执行链路

```mermaid
flowchart LR
    A[已审校公开包原件] --> B[原始 SHA 与学校官方域名核对]
    B --> C[生产 HTML/PDF 提取器]
    C --> D[生产年度识别与质量准入]
    D --> E[临时 SQLite 的提取版本与结构片段]
    E --> F[冻结关键词 + 学校/真实年度过滤]
    F --> G[前 8 个命中 + 每个前后 3 片段]
    G --> H[每次最多 12000 字符补读]
    H --> I[逐字跨度/真实页码/完整证据覆盖核验]
```

索引内容来自重新提取的完整原件。金标的答案、期望年份和引文不写入索引；来源年份使用生产 `_document_scope` 从实际标题识别。离线重放验证学校官方域名归属，沿用原归档时间，不伪造新的联网核验时间。

先执行片段内全部关键词匹配。没有严格片段命中且查询包含多个词时，生产检索仅在**同一当前提取稿全文包含全部词**的文档内，按片段命中词数定位。学校、年份、质量和有效状态先过滤；没有跨学校无条件扩大到任意单词匹配。这仍是确定性的关键词定位，没有使用向量模型。

全部读回文字必须满足 `text == canonical_text[char_start:char_end]`，跨度按 Unicode 码点，PDF 页码按实际物理页。跨页表头是独立的上下文引用，不拼成虚构连续引文。金标旧提取稿与新提取稿的空白差异只用于建立评测位置映射；重复引文需要整页或全文空白规范后完全一致才能利用冻结位置确定第几处，不能默认找到第一次。

**结论必须按实际结果写：**

- 混合检索与冻结查询基线来源召回相同，但完整必要引文和可信引文覆盖都更低；本语料上没有观察到全面质量提升，不能宣传“混合检索优于全部 BM25 或其他 RAG”。
- 自然语言关键词臂 0/31 不是“混合检索赢了”。当前 N3 关键词作用域把整句中文按空白拆成一个检索词并要求整段出现在同一片段，整句自然语言因此无法命中；这是已记录的关键词实现边界，本次没有改分词或换 BM25 来制造提升。
- 语义通道有真实成本：32 次本机 Embedding、1200 输入 token，平均延迟约为冻结基线的 11 倍。打开页面或轮询不产生这些调用，只有用户主动提交「混合检索」才可能计费或推理。

索引由 25 份合格来源、1891 个合格片段生成 1957 个向量窗口；本次构建 1956.043 秒，1834 个输入实际生成、123 个缓存命中、185367 输入 token，用量已知。冷启动首次混合查询 3974.292 ms，关键词预热 309.933 ms，二者不计入配对统计。

三题年度挑战（PF02、catalog-11、catalog-12）中，无年来源没有进入可检索向量，三条臂都未返回该来源；`publication_chain_runtime_supported=false`，未把元数据年份授予 PDF，也未观察到年份串用。这些结果只验证本地检索通路，不代表回答准确率、报考条件正确性或全国资料覆盖。
