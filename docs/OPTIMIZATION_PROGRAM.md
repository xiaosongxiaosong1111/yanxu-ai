# 研序优化计划（2026-11）

本文件是当前优化工作的项目台账：目标、工作流、检查点、指标、已做决策和下一步。
它不替代 `PRODUCT_CONTRACT.md`（产品边界）、`VERIFICATION.md`（验收证据）和
`RUNNING.md`（运行方式）。任何与代码冲突的描述，以测试和已发布快照为准。

## 1. 目标与非目标

**目标**：让考生从“查到资料”走到“能核对、能比较、能行动”，并且每个结论都能回到
原文、原文链接和适用年度。优化以可复现的程序计算为主，模型只做检索、抽取和解释，
不代替资格判断，不输出录取概率。

**本期做**：考研方向的信息发现、原文核验、候选比较、条件补齐、排名稳定性、地区/
学校分散、知识库与技能评测、前端最后一公里。

**本期不做**：考公；录取概率预测；用模型补造缺失字段；把未核验内容写成已确认事实。

## 2. 不可破坏的约束

1. 三态结论：`明确匹配` / `待确认` / `明确冲突`。未知条件不按默认值补齐。
2. 所有对外事实必须绑定来源；检索结果标记为
   `official_domain_unverified_content`，直到原文核验通过。
3. 算法输出确定性：同一输入、同一快照、同一版本应得到同一结果。
4. 本地服务只监听回环地址；密钥只进入本地加密设置库，不写入仓库、日志或报告。
5. 冻结原文、金标、采集器保持逐字节不变；运行库、模型缓存、生成的索引不提交。
6. 不把“影响度”“稳定性频率”“分散顺序”表述为录取概率或录取机会。

## 4. 检查点与通过标准

### C0 基线可信
- 全量 Python 测试通过；前端 Node 测试通过；工作树改动可解释。
- 通过标准：失败数为 0，跳过项有明确原因，测试使用临时数据。

### C1 来源发现可信
- 元宝 API 成功、空结果、错误、超时、超大响应均有确定处理。
- 官方域名过滤不可绕过；`Site` 回退必须显式标记 `site_fallback`。
- 通过标准：真实查询返回可打开的官方域名链接，且响应不含密钥。

### C2 证据可核对
- 每个事实能定位到文档、链接、页码和逐字引文；证据不足时结论降级为待确认。
- 通过标准：抽样事实 100% 可回到原文；近重复来源不被当作独立佐证。

### C3 决策可解释
- 同一输入重复计算结果完全一致；缺失字段不补造；不出现概率措辞。
- 通过标准：VOI、稳定性、分散项均能解释“为什么”，并明确其非概率含义。

### C4 用户可完成
- 从提问、补充条件、查看证据到导出/复核形成闭环；手机宽度无横向滚动。
- 通过标准：真实任务在预算内完成，空态和部分完成态都有下一步。

## 5. 指标

| 维度 | 指标 | 口径 |
| --- | --- | --- |

| 可靠性 | 测试通过率、失败恢复率、预算耗尽率 | 全量回归 + 真实任务 |

## 6. 已做决策（轻量 ADR）

- **AD-01 三态而不是二态**：资格结论必须允许“不知道”。理由：缺失条件时二态会制造
  假阴性或假阳性；用户需要知道下一步确认什么。
- **AD-02 不输出录取概率**：历史分数线和招生计划只能做参考区间与条件比较，不能
  从非随机样本推导个人录取概率。所有 UI 明示“不是录取概率”。
- **AD-03 VOI 只衡量候选集合变化**：优先级 = 选项改变前 k 名的频率、首选变化和位移
  的加权；不是“录取机会提升”。
- **AD-04 稳定性用显式情景**：只枚举用户可理解、可回答的条件组合；频率表示在前 k
  名中出现次数，不是概率。
- **AD-05 MMR 分散只改展示顺序**：不改变资格、分数或已填条件。没有明确匹配时，
  最多展示带“待确认”标签的候选，并明确“不代表已通过资格核对”。
- **AD-06 地区问题不重复**：硬性地区未填时只问 `provinces`；填写后才问
  `preferred_provinces`，避免两个问题描述同一缺失信息。
- **AD-07 检索空结果不是错误**：元宝 `SearchPro` 在无命中时可能省略 `Pages`。
  有 `RequestId` 且回显 `Query`/`Version` 时视为合法空结果；`Site` 过滤无命中时
  回退一次无 `Site` 查询，仍按官方根域严格过滤。`Site` 只匹配已索引的精确主机，
  所以“有 `Pages` 但全部是非官方域名”也视为本次过滤无命中并回退一次；回退结果
  同样没有官方链接时，保留受限的 `Site` 结果并把被拒数量如实上报，不把两次
  付费查询都算成有效来源。两次都无官方结果时，再用一个更宽的检索词
  （`学校 研究生院 年份 资料类型`）尝试一次；响应返回 `queries_tried` 与
  `outcome=no_official_results`，并说明“本次没有可展示来源，不代表资料不存在”，
  同时给出核对官网或换用更具体年份/专业的下一步。检索词阶梯在首个有官方结果的
  查询处停止，避免无谓的付费调用；结果按 URL 去重后返回。
- **AD-08 回退必须可见**：任何放宽查询范围的行为都在响应中标记，不能静默改变语义。
  候选检索也遵循同一原则：自然语言检索词无命中时，最多用 4 个拆分词重试，
  优先 3 位科目代码，其次专业词，最后才是学校名；结果返回
  `requested_query`、`effective_query`、`query_relaxed` 和提示，并写入
  `report.coverage.selection`，前端在候选区显式展示，不能只让模型看见。
  只有扫描完整且确实零命中时才放宽；版本切换、超时或分页中断的部分扫描
  不触发放宽，以免掩盖尚未完成的查询。
- **AD-09 证据覆盖不等于真实性**：`evidence_ledger_v1` 只统计可回到原文的链接、
  逐字引文和定位；同一引文出现在多份文档时按一个来源理解，并单列重复提醒。
  它不会把 `待确认` 升级为 `明确匹配`。
- **AD-10 可恢复的服务失败保留部分成果**：模型服务超时、限流、响应无法识别时，
  任务标记为 `partial` 并写入安全原因，不伪装成 `completed`，也不丢弃已获取资料；
  只有不可恢复的内部异常才标记 `failed`。
- **AD-11 重复付费调用不重复执行**：同一轮内 `search_official_sources` 或
  `read_official_source` 的工具名与参数逐字节相同时，直接复用首次结果，
  标记 `repeated_call` 并说明未重复消耗预算；不缓存错误，也不把复用写成新的
  联网核验。本地目录与知识检索不缓存，因为版本或代次可能在同一轮内变化。
- **AD-12 来源分层，第三方只能做线索**：默认只检索官方根域（学校官网、
  `yz.chsi.com.cn`）。用户显式选择 `scope=extended` 时才额外执行一次参考导向
  查询（`学校 考研 经验 报录比 参考书`），只接受白名单第三方站点（中公、考研帮、
  中国教育在线、新东方在线、文都、研途），逐条返回
  `source_tier=third_party_reference` 与 `source_name`，前端显示“第三方参考 ·
  未核验”；`outcome=extended_reference` 表示只有线索、没有官方结果。第三方
  内容永远不能升级为事实，也不能替代官方原文核验。
  实测边界：元宝 `SearchPro` 对 `offcn.com`、`yantu.com`、`kaoyan.com` 的
  `Site` 查询返回 0 页，说明这些站点未被索引；带年份的参考查询也会被测试/聚合
  站占满。因此扩展检索使用不带年份的参考查询，实际召回的是
  `kaoyan.koolearn.com` 等被索引站点，并如实标注来源，不把“没召回到中公”
  写成“中公没有内容”。
  官方资料目前只覆盖索引中 135/936 个单位（51 个 verified、84 个 partial），
  远不足以宣称全国完整，因此扩展检索是必要的补充，但必须可见、可追溯。

- **AD-13 页面与 Agent 共用同一条检索通路**：检索词、`Site` 回退、分层、
  去重、失败阶段与提示语统一放在 `official_search.py`，页面接口与
  `search_official_sources` 只提供各自的 `call` 与预算。`AITransport` 对
  元宝响应统一执行 `checked_response` 后再返回，调用方不再各自解析
  `Response` 外壳；合法空响应（省略 `Pages`，带 `RequestId` 和 `Query`/
  `Version`）在传输层规范成 `Pages=[]`，所以页面与 Agent 都不会把“有效空响应”
  误报成“响应无法解析”。预算按真实外部请求计数，而不是按工具调用计数：
  `Site` 回退和多一个检索词都会各计一次；额度不足时提前停止并返回
  `budget_exhausted=true`。共享响应新增 `request_count`、`failure_stage`
  （`official_found` / `binding_missing` / `attribution_unverified` /
  `third_party_only` / `domain_mismatch` / `index_no_hit`）、
  `binding_status` 与 `binding_domains`。Agent 已付费响应里出现的第三方页面
  直接按 `third_party_reference` 标注，不额外发一次线索查询；页面只有
  `scope=extended` 才执行一次专门线索查询。
- **AD-14 官网绑定必须带证据，且允许同校多域**：`unit_bindings.py` 只在
  每个域名都记录 `url`、`evidence`、`relation`、`evidence_quote` 和
  `checked_at` 时才采纳；登记目录本身 `official_url` 之外的第二域名
  （如中国科学院大学 `ucas.edu.cn` 与招生站 `ucas.ac.cn`）必须由已读官方页面
  证明关系。部署侧可在 `data/official_bindings.json` 追加同一结构的复核行，
  缺少 URL 或证据、指向研招网、端口/凭据异常的记录一律忽略。简称消歧也来自
  这张表（`国科大`→中国科学院大学、`社科大`→中国社会科学院大学），
  `find_units` 返回 `matched_by`、`aliases` 和 `alias_resolution`；简称已解析
  但索引无条目时返回 `reason=alias_resolved_without_index_match`，而不是
  用空列表暗示学校不存在。没有证据的学校保持 `official_url` 为空，检索响应
  明确写 `binding_status=missing` 和“这不代表官网没有资料”，不把缺绑定说成
  官网无内容。
- **AD-15 已核实官网登记为可读入口，站内发现受预算约束**：`find_units` 只在
  查询唯一命中一个学校（或命中简称的规范名）时返回 `official_source_id`，
  避免把某校入口挂到宽泛查询上；`read_official_source` 读取后把同站
  `<a href>` 入口（含导航与附件 PDF）登记成 `official_link` source_id，
  过滤外站、研招网、带凭据、非 HTTP(S) 和跨端口链接，逐跳保留归属检查。
  `discover_official_links` 支持 `depth=1|2`，只排序已读取页面上的同站入口，
  不再访问任意 URL；深度 2 的补读仍走 `read_official_source` 的官方域名、
  归属、完整性、SSRF 与研招网门禁，并受 `max_discoveries=2`、
  `max_navigation_fetches=4`、`max_links=20` 和原文读取预算限制；每个更深
  入口返回 `parent_url`，访问失败逐条记录，不把失败静默当成没有资料。
- **AD-16 搜索门户与聚合站不能成为官网候选**：缺绑定学校会得到
  `official_domain_candidate` 线索，但候选过滤必须排除已知搜索门户与第三方
  聚合站（如 `qq.com`、`yanzhaowang.com.cn`、`yzw.org.cn` 及既有第三方白名单）。
  这些站点即使在同一主机重复发布多篇带校名的招生文章，也只能作为第三方线索，
  不能因为“同主机多页”被提升为官网候选。候选仍不是官方结果，仍须人工或用
  官方页面证据登记绑定；`official_domain_unverified_attribution` 不参与任何
  招生事实确认。2026-11-05 真实审计发现 `so.html5.qq.com`、
  `yanzhaowang.com.cn` 与 `yzw.org.cn` 曾因重复页进入候选，加入该门禁后
  复测已移除，同校 `*.edu.cn` 候选保留。


- **AD-17 用户怎么输，目录就怎么查**：目录检索按空格拆分关键词并要求全部命中
  （`南开大学 计算机`、`计算机 408`），不再把整串当一个子串；`专硕/学硕/非全`
  同时匹配字面词和目录用词（`专业学位/学术学位/非全日制`）。简称按
  `unit_bindings` 的已复核别名表展开（`社科大 计算机` → `中国社会科学院大学
  计算机`），未知词保持原样，绝不据此猜学校。页面在提交检索时只在查询明确
  包含唯一校名或简称时自动切换研究范围；嵌套校名（如“北京大学”与“北京大学
  医学部”）以精确词优先、同层取最长，无法唯一确定时不切换。前端本地筛选与
  服务端使用同一套 AND 语义和别名表。`study_mode`/`degree_type` 已写入新的
  搜索文本，但当前已发布索引是旧文本，需下一次发布后才支持“非全日制”这类
  仅存在于这两个字段的检索；简称与多关键词不依赖重发索引。


- **AD-18 Skill 的“完成”必须有可核对结果，知识库简称只在零命中时展开**：
  （1）`research-official-sources` 的 `checked` 只能由带实际年度的
  `official_original_read` 或 `published_snapshot` 满足；`search_lead` 有链接、
  有年度字段也不能把 Skill 标成已检查，因为它没有可读原文。（2）五份 Skill
  的正文必须写明 `binding_missing`、`attribution_unverified`、
  `third_party_only`、`domain_mismatch`、`index_no_hit` 各自的含义，并明确
  它们都不等于“官网没有资料”；候选域名和第三方页面只作线索，不进入证据台账。
  （3）知识库检索在首次零命中且查询含已复核简称时才用规范校名重试一次：
  Agent 的 `search_knowledge`、`search_knowledge_segments` 与页面
  `/api/knowledge` 一致，仅第 1 页、不扩大学校范围，响应明确写出
  `requested_query`/`effective_query`/`alias_expanded`，页面显示“这只是检索词
  变化，不是新的资料或事实”。（4）零命中不会返回其他年度的资料；若库中确有
  其他实际年度，只返回 `stored_years` 提示并说明“不能把历史年度当作目标年度”。
  （5）系统知识预取只在查询唯一指向一个学校时按该校范围检索（`infer_unit`）：
  已复核简称和正式校名都参与匹配，嵌套校名取最长（北京大学医学部优先于北京
  大学），两个不同学校同级命中时保持全局预取。真实运行曾出现“国科大”任务复用
  另外 6 所学校留档并列入证据；修复后同条件任务的证据只保留目标学校。

## 8. 下一队列（按优先级）

1. **证据台账**：claim→evidence 对照，近重复/同源检测，缺证据自动降级。
2. **真实数据回归样例**：固定 3–5 个专业，覆盖明确匹配、待确认、冲突和空结果。
3. **检索评测**：金标查询集、Recall@k/nDCG、cross-encoder 影子模式与回退门槛。
4. **Agent 预算与恢复**：分层预算、失败重试、部分完成的可行动摘要。
5. **前端走查**：真实报告的长文、空态、移动端、键盘与对比度。
6. **发布门槛**：目录完整性、证据完整性、回环绑定、备份恢复演练。
7. **重建并发布目录索引**：让 `study_mode`/`degree_type` 进入 `search_text`，
   使“非全日制”“专硕”等词在真实库生效；需按发布流程重建快照并复核 936 个
   单位的专业数不减少。
8. **缺绑定学校的官网证据**（用户要求暂时搁置）：优先复核两轮审计的 11 个
   候选（首轮 3 个、第二轮 8 个）和两轮缺绑定单位，逐域读取官方页面并登记
   evidence；不按域名后缀或同名文章猜测官网。

## 9. 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 官方源改版或删除 | 事实失效 | 快照 + 校验和 + 失效降级，不静默沿用 |
| 检索索引覆盖不足 | 找不到原文 | 严格域名过滤 + 多查询回退 + 明确空态 |
| 模型预算耗尽 | 任务部分完成 | 分层预算、规则优先、可续跑 |
| 近重复来源冒充多源 | 过度自信 | 来源独立性检测，单一来源不升级结论 |
| 用户把影响度当概率 | 决策误导 | 固定措辞、UI 明示、测试锁定 |
