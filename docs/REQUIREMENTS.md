# 研序 AI · 产品需求与验收标准

> 项目：`yanxu-ai` · 更新：2026-11-03 · 本文记录当前需求基线与实现边界，供产品讨论、开发和 AI 接手使用。

研序 AI 面向全国考研规划，把宽泛想法转成有出处、可比较、可继续研究的候选方案。元宝搜索负责发现官方资料，AI 负责理解问题和组织研究，确定性算法负责比较条件与备考成本，知识库负责积累经过准入检查的来源。

当前默认服务 **2028 年入学规划**，目录参考年度为 **2027 年**。支持检索全国官方来源，不代表每次研究已经遍历全国，也不代表全国专业目录及历史数据已经全部收齐。具体发布数据与验证记录见 [README](../README.md) 和 [验收记录](VERIFICATION.md)。

## 1. 用户与核心问题

| 用户情境 | 要解决的问题 | 期望得到的成果 |
| --- | --- | --- |
| 只有大致专业意向 | “想考计算机”，不知道从哪些学校、学院和方向开始 | 可调整范围的候选清单、必要的澄清问题 |
| 已复习部分科目 | 希望少换专业课，又不想遗漏其他选择 | 按考试单元核对的衔接结果、0/1/2 单元调整路线 |
| 在学校之间取舍 | 科目、年学费、学制与地区信息散落在多个网页 | 相同口径的对比、排序依据和明确缺口 |
| 担心一志愿失利 | 想了解所选科目与历史复试、调剂要求是否衔接 | 逐年度、有出处的规则匹配，不把历史相容当作当前有名额 |
| 需要判断信息可信度 | 搜索摘要、官方原文、历史公示容易混淆 | 原文链接、实际年度、页码或字段路径、核验与冲突状态 |
| 长期研究多个选择 | 同一份资料反复搜索，缺少自己的资料积累 | 可追溯、去重、有准入门槛的本机知识库 |

## 2. 产品边界

### 2.1 当前交付

- 独立研究任务、条件确认、增量进度、停止与继续研究。
- 全国单位索引、已发布目录的分页查询、专业与科目筛选。
- 资格三态、完整科目身份比较、偏好排序、Pareto 前沿、备考路线及最小条件调整。
- 官方来源核验、历年资料与图表、历史复试/调剂规则匹配。
- 本机来源知识库、质量分区、实际原文留档和版本追溯。
- AI 模型连接、模型目录读取、生成测试、元宝两种鉴权方式与安全保存。

### 2.2 不作为当前已完成能力宣传

- 全国全部专业、考试科目、资格、历年成绩和报录比均已完整。
- 从任意新网页自动生成已经审校的招生字段，并直接加入算法。
- 预测录取概率、保证可以报名或保证调剂成功。
- 面向公网的多用户账号、跨用户数据隔离、管理员体系。
- 邮件、短信、公众号等跨渠道主动推送，以及无人值守的全国持续采集。
- 市面所有厂商、所有模型均已用真实凭据验证。

## 3. 功能需求

### 3.1 研究 Agent

| 编号 | 需求 | 当前行为与验收要点 |
| --- | --- | --- |
| AG-01 | 从自然语言开始 | 不要求先选专业 ID；保存原问题，未配置模型时进入等待连接状态 |
| AG-02 | 澄清关键条件 | 相对年份、学历、学习方式和备考科目等未知信息保持未知；一次优先询问最多三项关键问题 |
| AG-03 | 条件须用户确认 | AI 提案逐字段附用户原句；确认前不覆盖已填条件，不静默放宽限制 |
| AG-04 | 研究工具受控 | 只能调用服务端白名单；不允许模型执行 shell、任意代码或任意 URL 读取 |
| AG-05 | 搜索与算法协同 | 先复用合格知识与已发布目录，按需元宝检索和读官网原文；已有候选后程序确保实际匹配核算 |
| AG-06 | 控制重复与费用 | 每轮有限预算；取消后不启动后续调用，重启不自动重放研究；预算不是精确费用上限 |
| AG-07 | 多轮成果独立 | 本轮条件与算法重新计算，上轮报告单独保留；事件按轮次归属 |
| AG-08 | 进度真实 | 事件来自实际工具与状态；模型、搜索、原文、缓存和算法调用分别计数，不展示伪造思考过程 |
| AG-09 | 先筛选再精选 | 在已发布目录的学校/年度/关键词范围内先硬筛和粗排，再跨校精选最多12项；后续合适方向不能被首12条或隐含省份8校上限挡掉；不把未扫完标成完成 |
| AG-10 | 未形成候选仍可继续 | 保留来源、待核项与输入；不能把“尚未找到可计算候选”解释为该专业或学校不招生 |
| AG-11 | 排除意愿独立 | `excluded_subjects` 与已准备科目分开；必考禁项排除，合法替代重算；歧义套组和不明作用域不能变成符合 |
| AG-12 | 区分地区限制和偏好 | “只去天津”使用硬条件，“优先天津”使用软偏好；提案附原句、冲突与确认状态，软偏好不得覆盖费用/科目主排序 |

默认每轮上限为 8 次模型调用、4 次搜索、4 份原文、20 次工具调用、12 个候选、180 秒与 40,000 个累计模型用量 token；任务队列最多 4 项。具体常量以 [research_tools.py](../research_tools.py) 为准。停止策略依据厂商返回用量，不承诺供应商已接受的请求可撤销或退款。

### 3.2 院校、专业与历史资料

| 编号 | 需求 | 验收要点 |
| --- | --- | --- |
| DA-01 | 单位索引与目录覆盖分开 | 分别显示年度单位、已入库专业、部分目录、待采集和原文读取状态 |
| DA-02 | 真实专业与科目 | 保留学校、年度、院系、方向、学习方式、原始代码、考试单元、命题范围和备选组 |
| DA-03 | 缺失信息可见 | 未知费用不当免费，未知学制不默认三年，未收录不当不存在 |
| DA-04 | 历史数据按真实年份回溯 | 在最近三个已完成招生年度范围内展示可得数据；缺年留空，不将不同年度拼为同一组统计 |
| DA-05 | 成绩口径分开 | 学校线、学院线、专业线、录取初试统计、复试成绩和最终成绩规则分别保存和展示 |
| DA-06 | 历史图表有依据 | 仅绘可核验或可重放的统计；未知满分、来源失效或统计不一致时不绘为确定趋势 |
| DA-07 | 逐字段查看依据 | 展示精确原句、官方链接、页码或结构化路径、实际年度及适用范围 |
| DA-08 | 多依据与冲突 | 同源去重、版本分开、引用链不冒充独立印证；冲突字段暂停采用确定值 |
| DA-09 | 关注来源变化 | 保存订阅方向与基线，可检查新旧官方来源的变化；不把本站内变化记录宣传成跨渠道推送 |

全国资料扩充是持续数据工程工作。下载到原文、解析出候选、通过字段审校、整校目录对账通过是四种不同成果；任何一个数量都不能替代其余完成率。

### 3.3 可解释算法

| 编号 | 算法 | 必须保留的行为 |
| --- | --- | --- |
| AL-01 | 资格三态 | 返回 `matched / excluded / unknown`；目录完整性与资格完整性独立，不忽略未解析实质条件 |
| AL-02 | 科目衔接距离 | 身份为代码与命题范围，按考试单元比较完整备选组；跨校同代码、自命题同名不自动等价 |
| AL-03 | 科目未知处理 | 缺当前备考科目或科目身份待核时，距离为未知，不展示为零换科 |
| AL-04 | 偏好排序 | 区分综合、科目优先、费用优先；给出分项与排序依据，未知分项不按零计入确定总分 |
| AL-05 | Pareto 前沿 | 仅对条件匹配且有效分项完整的项目标识，表示取舍关系，不代表录取概率 |
| AL-06 | 换科路线 | 分别计算最多调整 0、1、2 个考试单元的覆盖与增减，保留其余已确认事实 |
| AL-07 | 最小条件调整 | 只枚举用户允许的科目数、地区与年学费组合，最多 128 个组合；不改变学历等硬事实 |
| AL-08 | 敏感性试算 | 明确展示情景条件变化后新增、移除、保留的方向；试算不自动保存成用户条件 |
| AL-09 | 历史复试/调剂匹配 | 按具体规则、年份和用户明确输入事实核对；历史条件相容不等于当年存在缺额 |

当前排序将 `provinces` 作为地区硬条件，`preferred_provinces` 在综合模式且地区权重大于0时参与加权；费用/科目优先保留主要排序依据。科目、费用和软地区分项均保留缺失值语义、解释和测试，地区零权重不能改变顺序。

### 3.4 知识库准入与复用

知识库的“取得状态”和“准入质量”是两个独立维度：

| 维度 | 状态 | 含义 |
| --- | --- | --- |
| 取得状态 | `search_lead` | 检索片段，尚未作为官方原文采用 |
| 取得状态 | `official_original_read` | 取得可核 SHA 的官方原文；不等于各字段已审校 |
| 取得状态 | `published_snapshot` | 来自已发布资料的引用；不等于本轮实时联网核验 |
| 准入质量 | `accepted` | 来源归属、实际年度、原文可用性和实质内容通过检查，可供后续研究复用 |
| 准入质量 | `pending` | 摘要、未知年度、归属待核、附件入口或资料类型待核，暂不自动复用 |
| 准入质量 | `excluded` | 门禁、纯导航、代码噪声、明显无关或个人名单等被拦截 |

| 编号 | 需求 | 验收要点 |
| --- | --- | --- |
| KB-01 | 有门槛地积累 | 搜索摘要永远不直接通过；只有目录标题或下载链接不能当作目录正文 |
| KB-02 | 正文实质检查 | 专业、科目、费用、条件等须有与类型相符的信息；标题年份、页脚邮编和长导航不充当事实 |
| KB-03 | 不以长度决定质量 | 很短的明确科目调整可以通过；未知或无法判断的材料保留待核 |
| KB-04 | 分区与原因可查 | 默认显示可复用资料；待核、已拦截、全部来源可切换，每条展示准入理由 |
| KB-05 | 版本与去重 | 同 URL 不重复积累弱摘要，同原文 SHA 不算独立印证，新版本保留；弱记录不覆盖旧强记录 |
| KB-06 | 复用真实原文 | 同链接命中旧强记录时采用其真实正文、年度、SHA 和读取时间，不给新摘要贴旧的认证 |
| KB-07 | 失效撤信 | 原文丢失或同长度篡改时撤销正文信任与复用资格，过滤、分页和计数保持一致 |
| KB-08 | 保护个人资料 | 不导入私人问题、用户条件或服务凭据；名单正文不进入模型或公开知识阅读界面 |
| KB-09 | 失败与拦截分开 | 按规则过滤不是保存故障；保存失败必须在报告显示，不能虚报已入库 |
| KB-10 | 缓存仍需年度核对 | 仅复用 `accepted` 且 `reusable=true` 的资料，并再次核对年度、取得状态和原文可用性 |
| KB-11 | 结构与精确补读 | 第21页和旧预览之外条款可定位，表头/章节与正文分别引用，页码和 Unicode 跨度属于同一提取版本 |
| KB-12 | 有效性独立维护 | 撤信、冲突、替代阻断复用；采用版本必须同原文范围及实际年度，不跨年自动选择 |
| KB-13 | 索引失败可恢复 | 新代次失败保留旧可用代次和失败任务；重复重建幂等，旧任务不能复活已撤信资料 |
| KB-14 | 历史成果复核 | 再次打开报告和上轮报告时复核当前来源，旧摘录与可信解释不得因历史缓存继续有效 |
| KB-15 | 资料阅读与维护 | 精读、上下文、邻接和官方定位为主要流程；维护收在折叠区，状态变更需理由与明确确认 |
| KB-16 | 可复现真实评测 | 34道问题绑定官方原件、SHA、原句、页码/跨度；检索、读齐引文及未知挑战分别计数 |

新拦截内容不进入知识库；旧记录重分类时保留离线审计，API 和全文索引不提供拦截正文。知识准入不能直接把网页值写入正式招生资料或绕过字段级审校。

### 3.5 AI 与元宝连接

- 预置 16 个厂商/接入选项，提供适用的端点默认值、模型读取或手填入口。
- 模型目录成功不等于当前 Key 有生成权限。连接测试须真实生成，保存须绑定有效测试收据；改变厂商、端点、模型或凭据后重新验证。
- 元宝支持腾讯云标准 `SecretId + SecretKey` 与服务 `API Key`，二者独立测试、保存，禁止拼接不同来源的凭据。
- 显示未配置、未测试、已连接三态。AI 与元宝互相独立，保存一种连接不影响另一种。
- Windows 使用当前账户 DPAPI 加密；非 Windows 为明确的会话存储，重启后重新配置。Key 不回显、不进入 URL 或浏览器持久化存储。
- 新 Agent 走 `/api/research`；旧 `/api/chat` 兼容接口未接通，不把它作为新的对话入口。

## 4. 交互与视觉要求

1. 延续冷白、炭黑、少量钴蓝的界面；正文、表单和按钮保持可读字号，移动端不横向溢出。
2. 主导航为研究、院校专业、我的方案。配置和知识库使用独立页面，不把所有功能按钮堆在同一张表单。
3. 研究输入先于结果，运行中可写草稿；进度日志折叠，同校方向合并，优先展示少量学校与关键取舍。
4. 后台刷新须保留正在编辑的原生输入框及祖先节点，不打断中文组词、选区和撤销记录；组词期间不快捷提交。
5. 停止并更新须等待旧任务真正可继续，再单次提交。发送成功只清理已消费的草稿，保留后输的新稿与迟到输入。
6. 来源、年份、缺失项和核验状态贴近相关结果；不使用与实际状态无关的固定警告替代进度说明。
7. 加载、空结果、配置缺失、限频、暂时错误、取消与部分完成均有明确的下一步。迟到响应不得覆盖当前选择。
8. 表单有标签，键盘可操作，切页与详情返回保留合理焦点；图表信息不能只有颜色提示。

## 5. 数据与非功能要求

| 方面 | 要求 |
| --- | --- |
| 数据分工 | 源资料 JSON、明确发布的查询 SQLite、动态知识库、研究任务、连接配置分离 |
| 发布 | 修改源 JSON 不自动成为线上查询版本；离线重放、年度核准和语义审校后事务发布，失败保留旧版 |
| 原文依据 | 保留真实 URL、SHA、读取时间、页码或字段路径；不得拼造官方逐字引文 |
| 查询性能 | 正式前端使用轻量启动和分页接口；大 JSON 使用项目分块读取器，不将全库直接下发浏览器 |
| 安全边界 | 默认仅回环地址；同源 JSON POST、输入校验、限频、公共端点约束和安全错误信息持续有效 |
| 密钥隔离 | 配置仅作用于本项目，不借用其他应用凭据；运行时数据不作为源码发布 |
| 采集边界 | 官网归属与来源范围校验；访问门禁、登录和频控不通过清状态或换身份绕过 |
| 可维护性 | 新事实类型、新算法维度和新工具均有契约、解释和相应回归，不靠模型自由文本补齐正式字段 |
| 源码与数据分发 | 源码与通过分发审查的压缩资料包分别管理；私人运行库、完整采集缓存及逐人名单原文不提交 |
| 克隆可复现 | 公开资料包须有逐文件路径、字节数与 SHA；离线恢复校验后再发布查询版本，不能依赖开发机已有 SQLite |
| 已有数据保护 | 恢复时相同 SHA 可跳过，不同内容拒绝覆盖；不通过删除原资料、放松审校或补假数据获得“发布成功” |

## 6. 验收矩阵

| 场景 | 必须观察到的结果 |
| --- | --- |
| 无模型配置发起研究 | 问题保存、等待连接，不出现伪检索与伪答案 |
| 只有模型列表读取成功 | 不显示生成验证成功，不允许用未验证模型跑研究 |
| 用户说“明年”或漏填备考科目 | 保留歧义或未知并请确认，不把默认值伪装成用户回答 |
| 同代码、不同学校自命题 | 不自动算作同一科；缺完整套组时不显示零换科 |
| 有目录但缺资格章程 | 可展示和比较已知信息，资格仍待核，不能认定可申请 |
| 搜索到摘要或目录下载页 | 进入待核，不计为可复用原文或完整目录 |
| 原文丢失或遭篡改 | 撤信、隐藏旧正文，不继续作为可靠缓存命中 |
| 资料被规则拦截 | 显示原因，不写成保存失败或成功知识积累 |
| 连续轮询中中文组词 | 原生节点不移出 DOM，中文正确提交一次，进度继续更新 |
| 等待取消时离页 | 不在后台自动继续提交；草稿按现有页面生命周期保留 |
| 多年数据缺一年度 | 图上留空、年份真实，不用另一年数字补位 |
